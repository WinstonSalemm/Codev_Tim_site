# Codev_Tim: production-like аудит и исправления

Дата: **10 сентября 2026 года**, Asia/Tashkent. Исходный коммит: `520b852` в `main`.

## Среда и охват

Сборка завершилась успешно с проверкой типов и lint; Next.js 15.5.20 сформировал 69 маршрутов, включая служебные и отключённые. В действующем sitemap **48 публичных страниц**.

## Исправлено

1. **Ошибка гидратации UZ.** Сервер и браузер по-разному форматировали сентябрь: встречались `30-sentabr` и `M09 30`, что вызывало React #418. Названия месяцев RU/UZ/EN теперь детерминированы; граница акции учитывает Ташкент и исключительный момент окончания. Проверены переход года и високосная дата.
2. **Мобильное меню.** Добавлена доступная кнопка закрытия внутри открытого меню, локализованная подпись, управление фокусом и закрытие при переходе к desktop-ширине. Ранее шапка с единственной кнопкой оказывалась недоступна при открытом меню.
3. **Узкие экраны.** На 320 px узбекские стартовые цены выходили за доступную ширину. Цены перестроены в строки; кнопки выбора типа проекта на телефоне используют две колонки. Финальные 320/390/768 px перепроверены.
4. **Формы.** Добавлены локальные сообщения ошибок RU/UZ/EN, связь ошибок с полями, фокус на первом ошибочном поле и подтверждении, блокировка отправки и настроек на время запроса. Ошибка доставки сохраняет введённое; успешная отправка позволяет начать новую заявку.
5. **Калькулятор.** Число страниц можно временно очистить и набрать заново. При выборе готового пакета отображаемое число синхронизируется с расчётом. Проверен переход с восьми страниц на корпоративный пакет: пять страниц и 5,5 млн сум.
6. **CTA услуги.** Переход к контактам теперь называется обсуждением выбранного варианта. Название «Настроить проект» сохранено там, где действительно открывается настройка калькулятора.
7. **Аналитика заявок.** Добавлены `generate_lead`, `form_error`, `contact_click` с разрешёнными категориальными параметрами. Успех фиксируется после подтверждения доставки; honeypot не считается лидом. Собственные события не содержат имя, телефон, email или текст сообщения; URL страницы очищается от query/hash. На localhost сторонняя аналитика не загружается. Текст Telegram-заявки формируется при нажатии, а не хранится в DOM-ссылке.
8. **Robots и canonical.** Убран запрет `/_next`, мешавший обходу JS/CSS; объединены правила роботов. Публичный fallback origin — `https://www.codev-tim.uz`, с нормализацией и проверкой URL.
9. **SEO услуг.** Локализованы title, Open Graph и Twitter metadata, canonical/hreflang. Offer-разметка соответствует минимальным видимым ценам UZS, акции и месячному периоду поддержки. Неизвестные имена услуг, включая свойства прототипа объекта, возвращают 404 вместо ошибки 500.
10. **Контраст и проверки.** Исправлены проблемные цвета второстепенного текста, ошибок и текста на акцентных кнопках. Валидатор читает реальные CSS-токены вместо отдельного устаревшего набора. SEO-проверки обновлены под действующие страницы; добавлен повторяемый HTTP-аудит.

## Проверка форм без реальных сообщений

На обычной production-сборке проверены серверная валидация, фокус ошибки, сохранение полей после отказа доставки, повторная попытка и наличие Telegram-резерва. Внешняя кнопка с подготовленной заявкой не нажималась.

Для успеха использован отдельный локальный production-сервер на loopback с имитатором Telegram: фиктивный токен, задержка ответа и блокирование настоящих Telegram/Resend-запросов. Выполнены ровно **три успешные тестовые отправки**:

- UZ: контактная форма с выбранным корпоративным сайтом; ожидание, подтверждение и сброс.
- RU: калькулятор сайта, зависимости каталог → корзина → оплата, серверная передача конфигурации, подтверждение и новая заявка.
- EN: контактная форма с выбором email; подтверждение и новая заявка.

Дополнительно проверено переключение калькулятора на CRM, AI, Telegram, поддержку и аудит. Для CRM и короткого брифа бота интерфейс не придумывает точную смету. После проверки сервер имитатора остановлен. Реальная доставка в боевой Telegram этим тестом не подтверждается.

## Повторение проверок

```powershell
npm run build
npm run start -- --hostname 127.0.0.1 --port 3100
```

В отдельном терминале:

```powershell
npm run test:commerce
npm run phase5:seo
npm run a11y:validate
node scripts/audit-production.mjs
git diff --check
```

HTTP-скрипт поддерживает `BASE_URL` и `EXPECTED_SITE_URL`. Подробный результат сохраняется в игнорируемом `data/production-http-audit.json`. Он выполняет GET-проверки, не отправляет заявки и не переходит по внешним контактным ссылкам.

## Что остаётся непроверенным

- Полевые Core Web Vitals, позиции/частотность запросов и индексация в Search Console: кабинеты и реальные пользовательские данные не исследованы. Оценка Lighthouse не подменялась размером JS или отсутствием ошибок.
- GA4/Clarity в боевом аккаунте: реализация проверена исходниками и тестами, получение событий кабинетом не подтверждено.
- Физические iPhone/Android и Safari: использован встроенный Chromium-браузер с разными viewport. Проверка контраста токенов не равна полному аудиту WCAG.
- Настоящая доставка Telegram/email: проверялся локальный транспорт-имитатор, без исходящих сообщений людям.
- Обновлённый Railway deployment: локальный build и Git push сами по себе не подтверждают опубликованный контейнер. До публикации `www` отвечал HTTP 200; обращение к домену без `www` из этой среды завершалось ошибкой DNS, что требует отдельной проверки DNS и перенаправления. Railway CLI не связан с проектом, а запрос списка проектов упирался в разрешение `backboard.railway.com`. Итог пуша и последующего публичного smoke приводится в сообщении о завершении.
