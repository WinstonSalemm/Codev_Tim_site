# Express Start — результат интеграции

Дата: 30 октября 2026. Ниже зафиксированы реализация и локальная проверка в существующем Next.js-проекте перед публикацией.

## Поведение

- Главная RU / UZ / EN: компактная ссылка на Express Start под стартовыми ценами; прежний «сайт» уточнён до индивидуальной разработки.
- Общий каталог: WEB / START перед индивидуальным лендингом. Краткий состав, $100, сроки после получения материалов, раскрываемые ограничения.
- `/[locale]/services/websites`: три формата — Express Start, индивидуальный лендинг, сайт компании. Обновлены описание, FAQ, метаданные и Offer JSON-LD.
- Калькулятор: отдельный фиксированный выбор Express Start без опций индивидуального проекта. Полный состав и существующая форма заявки. Кнопка заказа на главной и в каталоге переносит фокус непосредственно к выбранной форме; это проверено на мобильном экране.
- Индивидуальный лендинг остаётся от 3 000 000 сум, сайт компании — от 5 500 000 сум. Остальные базовые цены сохранены.
- $100 не пересчитываются в UZS и не отображаются как 100 сум. Оплата в сумах согласуется заранее. Express Start исключён из редактора скидок и серверного применения акций; просроченные акции не активны.

Новая UI-составляющая: `ExpressStartDetails.tsx` — общие условия о материалах клиента и ограничениях. Новый модуль `express-start.ts` хранит полный локализованный текст и краткий состав карточки. Дизайн, типографика, сетка, контакты и проекты переиспользованы; зависимости не добавлены.

## Заявки

На главной пакет выбирается внутри калькулятора; на странице услуг кнопка ведёт в существующий `/[locale]/contact?offer=web_start`. Форма показывает выбранное название и $100.

`offerId=web_start` передаётся существующему server action. Сервер находит пакет в каталоге и самостоятельно формирует имя, ID, фиксированную цену и примечание об оплате в сумах для сообщения владельцу. Подставленные суммы и запрещённые дополнения не используются; сочетание Express Start с индивидуальной конфигурацией отклоняется.

Сохранены проверка имени/контакта, состояния ожидания/успеха/ошибки и возможность повторить после ошибки. Синхронная блокировка защищает от двойного клика и повторного Enter. В локальном браузере двойной клик вызвал одну серверную попытку; доставка намеренно отключена, поэтому проверен честный ответ об ошибке и сохранение возможности повторить.

Аналитика использует существующий разрешённый набор событий: `offer_view`, `offer_cta`, единственный существующий обработчик `generate_lead` с `offer_id=web_start`. Контакты и содержимое заявки в параметры аналитики не добавляются. Локальные адреса исключены из аналитики.

## Ограничения проверки и существующие проблемы

- Реальные Telegram/email-уведомления не отправлялись; получение владельцем не подтверждено. Успешная серверная доставка и формирование сообщения проверены с тестовой заменой доставки, а браузерная отправка — с отключёнными каналами. Успешный экран после реальной внешней доставки не проверялся.
- Реальное получение аналитических событий GA4 не проверено; проверены код и разрешённый payload.
- Lighthouse не установлен в проекте; оценка Lighthouse и полевые Core Web Vitals не измерены. Размер First Load JS главной по build — около 167 kB.
- Общий `npm run format:check` завершается с предупреждениями в 43 существующих файлах вне изменений этой задачи. Эти файлы не переформатированы.
- Дополнительный старый `npm run phase5:search-rss` сообщает две ошибки: строковая проверка noindex поисковых результатов writing и RSS discovery главной. Соответствующие исходники и сам валидатор не изменялись в этой задаче. Это отдельные существующие замечания, не результат Express Start.
- Проверки в этом отчёте относятся к локальной production-сборке перед публикацией; результат production-релиза подтверждается отдельно.

## Конфигурация и ручные действия

Новых переменных окружения нет. Используется существующая серверная конфигурация `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CONTACT_CHAT_ID` либо альтернативный Resend (`RESEND_API_KEY`, `CONTACT_TO_EMAIL`, необязательный `CONTACT_FROM_EMAIL`). Секреты на клиент не добавлены. Для событий используется существующий `NEXT_PUBLIC_GA_MEASUREMENT_ID`.

Production-релиз выполняется после отдельного разрешения пользователя. После него отдельно проверяются успешный release, публичный путь заказа и при необходимости реальное получение тестовой заявки. Локальный QA-сервер остановлен после проверки.
